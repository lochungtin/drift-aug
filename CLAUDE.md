## Project status

DRIFT (**D**iffeomorphic **R**egional **I**nterpolation and extrapolation of **F**low **T**rajectories) is pre-release. **This file is the authority on conventions and design as built.** The research experiments, reports and original design notes are kept outside this package, in the `_drift_aug` folder of `lochungtin/PhD_Codebase`.

  - `uv run pytest` / `uv run pytest tests/test_package.py::test_version -x` — tests
  - `uv run ruff check . && uv run ruff format .` — lint/format (markdown is excluded from formatting)
  - `uv run mypy` — strict mode, checks `src/`
- Extras: `[io]` (nibabel, SimpleITK), `[niftyreg]` (no deps; binaries found via `bin_dir`, then `$NIFTYREG_BIN`, then `PATH`), `[viz]`, `[monai]`, `[torchio]`, `[dev]`.
- Test infrastructure (`tests/conftest.py`): the `ndim` fixture parametrises a test over 2D and 3D, and should be used by every core-math test. `tests/helpers.py` has synthetic fields (smooth random SVFs, rotation SVFs) and an `interior` crop; compare fields away from the border, since `compose` uses border padding. `@pytest.mark.niftyreg` and `@pytest.mark.gpu` tests auto-skip when the binaries or CUDA are missing; `@pytest.mark.slow` tests (real data, minutes) run only with `DRIFT_SLOW=1`. Don't run several GPU experiment processes at once: PyTorch's caching allocator keeps memory after a process's GPU work ends (an idle process held 4 GiB and OOM'd another run). `FakeRegistration` + `write_subjects` (also in `helpers.py`) build small banks without NiftyReg, so bank/augment tests run in CI.
- CI (`.github/workflows/branch-ci.yml`) runs on pushes to `main` and on pull requests. It installs CPU-only torch via `uv pip install --torch-backend=cpu`, runs lint + mypy on 3.12, tests on 3.10–3.13, and runs the `niftyreg` tests in their own job against a cached `scripts/build_niftyreg.sh` build. The MONAI and TorchIO adapters are tested in a third job. `pytest --cov` fails under 85 % coverage. On `main` it then builds, publishes to TestPyPI and bumps the version from Conventional Commits; the pushed tag triggers `release.yml` (PyPI and a GitHub release). The version comes from the git tag (hatch-vcs). Commit with Conventional Commits, and don't edit the version by hand.
- `data/` (gitignored) is the local place for datasets. `DRIFT_BREAST_DIR` points notebook 03 at a `<dir>/{images,labels}/<id>.nii.gz` dataset; without it the notebook falls back to synthetic phantoms. `tests/test_backend_regression.py` needs Duke data at `data/duke/{images,labels}`. `scripts/prepare_totalseg_thorax.py` selects TotalSegmentator MRI thorax scans and merges masks into the `thorax_mri` label convention. No patient data belongs in this repository.
- Registration masks without labels: `preprocess.foreground_mask` (smooth, Otsu, opening) before dilation. A plain threshold + 10 mm dilation turns background noise speckle into a mask covering the whole MRI volume (found on Duke). Morphology (`dilate`/`erode`) is separable 1-D max-pooling; a 3-D box `max_pool3d` with a 21³ kernel takes minutes on CPU at 20 M voxels.

## Core idea

Augment segmentation training data by moving a subject partway along an inter-patient deformation stored as a stationary velocity field (SVF) `v`: `φ = exp(w(x)·v)`. `t` (or a per-region weight map `w(x)`) may lie outside `[0,1]` (extrapolation). Every sample is a diffeomorphism; image and labels are warped with the same map, so labels stay exact.

## Conventions that must hold everywhere

These are the most likely source of silent bugs:

- **Compute backend is PyTorch** (`grid_sample`); NumPy only via thin wrappers.
- **Dimension-agnostic code**: spatial dim `D = v.shape[1]`; loops over axes for finite differences, smoothing, B-splines. 3D is primary; every math test runs in both 2D and 3D.
- **Fields are `(B, D, *spatial)` in voxel units.** Affine (sform), spacing and orientation are metadata on an `ImageSpace`; mm/orientation only matter at NIfTI I/O and NiftyReg boundaries.
- **`grid_sample` coordinate conversion and `align_corners=True` are set in exactly one place** (`grid.py`).
- **Pull-back warps internally**: `I_warped(x) = I(φ(x))`. Other conventions are converted by import adapters in `io.py`. Points are warped with the inverse map `exp(-v)`.
- **Exponentiation** = scaling and squaring, steps chosen automatically so each step is < 0.5 voxel from `max‖t·v‖`.
- **Combining regions**: sum weighted velocities, then exponentiate once (no sequential composition / BCH effects).
- **Regional modes**: Eulerian (`w` fixed in space; `exp(v, w)` or `integrate(..., lagrangian=False)`) vs. Lagrangian (`w` attached to the source tissue; default for regional). `flow.integrate` follows each point's path with RK4, plus a per-point Newton solve for the Lagrangian time `τ = w(ψ(x))`. It deliberately does **not** compose many small warps: that re-interpolates the accumulated map every step and gives O(1) numerical diffusion that more steps don't fix. The Lagrangian map is only invertible when `|∇w·v| < 1` (tissue mustn't collide), so `w` must be smooth.
- **Weight maps** (`weights.py`) are `(B, 1, *spatial)`; any time argument may be a float or a per-sample `(B,)` tensor. `sigma` is in voxels everywhere (`weights.sigma_voxels` converts from mm). `weights.rate(w, v) = max|∇w·v|` is the Lagrangian invertibility measure, and `limit_rate` enforces it (default 0.5): it smooths first, so times in region cores survive, and shrinks times towards the mean only as a last resort. Pass the velocity exactly as it will be integrated (e.g. `-v` for augmentation); `rate` uses the absolute value, so either sign is safe.
- **A displacement `u` means `φ = id + u`; `compose(u1, u2)` is `φ1∘φ2`.** Field channel `i` is the component along array axis `i`; `grid.to_grid_sample` does the flip to grid_sample's x/y/z order.
- **Soft label warping** gives mass pulled from outside the FOV to class 0, so out-of-FOV voxels are background rather than an argmax over interpolation noise.
- **Bank sign convention**: `v_AB` lives on A's grid (A fixed, B moving); augmentation samples `A ∘ exp(−t·v_AB)`. The sign is handled inside `FieldBank` and never exposed to users: `FieldBank.velocity(a, b, space)` already returns `−v_AB`. Only the non-rigid part is stored; affine is excluded by default (the npz keeps `registration_affine` for QC).
- **Bank storage and grids**: fields are stored as float16 on a grid with `profile.store_spacing` (same origin/directions as A's) and re-expressed on any requested grid of the same world frame by `preprocess.resample_field` (vectors converted through world mm). So `DriftAugment` can run on a different spacing than the bank was built on, if the sample carries its `ImageSpace` under `space_key`. `bank.json` is the index (subjects, pairs with QC, the full profile); building is resumable and skips existing pairs.
- **`DriftAugment`**: policy/rules/Lagrangian default from the bank's profile. Lagrangian regional draws go through `weights.limit_rate` (guaranteeing invertibility) before the det J / displacement rules; rejected samples are redrawn (new partner and times) up to `max_retries`, then the identity. When no deformation is accepted (or `prob` skips), inputs pass through untouched (a zero-displacement `grid_sample` is not bit-exact). Seeded per DataLoader worker.
- **Compartments (sliding interfaces)** (off in the thorax profile: on 20 TotalSegmentator chest pairs they gave no gain over one well-regularised field, cost 2.2× and strained narrow blend zones; keep `blend_sigma_mm` ≥ ~10): `registration.compartments` (label sets; an empty list means "rest of the body") makes `FieldBank.register_pair` register the whole body first, then each compartment with its own masks *relative to that affine* (the `Registration.register(..., affine=...)` argument; NiftyReg then skips `reg_aladin`), and blend the velocities with smoothed compartment indicators of A (a partition of unity, falling back to the whole-body field outside all compartments), exponentiated once. Still one diffeomorphism; true (discontinuous) sliding is approximated by a `blend_sigma_mm` transition zone. Needs labels for both subjects, otherwise the whole-body field is used.
- **Integrations**: `drift.integrations.monai.DriftAugmentd` (grid from the `MetaTensor` affine) and `drift.integrations.torchio.RandomDrift` (`ScalarImage` = image, `LabelMap` = labels). Both must run before random cropping. mypy treats monai/torchio as `Any` (`follow_imports = "skip"`) so CI, which doesn't install them, agrees with local runs; their tests `importorskip`. Install locally with `uv run --extra monai --extra torchio ...` (inexact, keeps the dev env). nnU-Net: `examples/nnunet_offline_drift.py` (offline copies + leak-free `splits_final.json`). CLI: `drift profiles | register | bank build/info | sweep | augment` (`cli.py`); a sample's `partner` key fixes the partner in `DriftAugment`.
- **Training with DRIFT on the GPU**: keep the bank's device cache small (`FieldBank(..., cache_bytes=2**29)`): the 2 GiB default plus a U-Net and Lagrangian buffers ran an 8 GB GPU out of memory. Regional DRIFT costs ~0.5 s/sample at 1.5 mm on an RTX 4060 (~80 ms with `DriftAugment(field_spacing=3.0)`).
- **Profiles** (`profile.py`) are strict: unknown YAML keys and wrong types raise. Labels are only integers in the core; names live in the YAML. Regions are painted in order (later on top); `split_axis` splits a region at its centroid (e.g. left/right breast after RAS reorientation); `follow_background` keeps e.g. lesions at the background time.
- **Site-agnostic core**: the library never names anatomy. All anatomy-specific choices (preprocessing, registration mask/params, label→region `t` ranges, QC bounds) live in `SiteProfile` YAML presets under `src/drift/profiles/` (breast MRI first, then thorax MRI). Breast (prone) and thorax (supine) banks are never mixed.
- **NiftyReg backend pipeline** (`registration/niftyreg.py`): `reg_aladin` → `reg_resample` B onto A's grid with that affine → `reg_f3d -vel` **without `-aff`**. If f3d gets `-aff`, it splits the affine into two half-affines around the velocity field (CPP extensions), so the SVF ends up in a half-way frame; `velocity_from_cpp` rejects such files. The CPP stores world-mm control-point *positions* on a world-axis-aligned grid, so it is evaluated with `bspline.evaluate` at the reference voxels' world positions (handles oblique/flipped sforms), then converted to reference voxel units. NiftyReg affines follow `Affine * reference_world = floating_world`.
- Known NiftyReg quirks: `reg_transform -flow` segfaults on 2D float64 images, so feed NiftyReg float32. `reg_transform`/`reg_measure` reject `-voff`. NMI barely registers binary or blurred synthetic shapes, so synthetic tests use SSD.
- Both registration backends (`registration/niftyreg.py`, `registration/torchreg.py`) implement the same `Registration` protocol and take parameters from the `SiteProfile` (`registration.backend: torch | niftyreg`, built by `RegistrationConfig.make()`). **torch is the default** (validated on labelled Duke: Dice 0.924 vs NiftyReg 0.905, no QC failures, ~4.6× faster on GPU; TotalSegmentator thorax 0.802, 20/20 pass); NiftyReg stays the reference. `tests/test_backend_regression.py` compares them on fixed Duke pairs (`DRIFT_SLOW=1`, needs `data/duke`); run it after changing `torchreg.py` or the calibration. Tests that mean NiftyReg must set `backend="niftyreg"` explicitly.
- **torchreg**: the implementation now comes from the `pyniftireg` package (PyPI, extracted from this module; github.com/lochungtin/pyNiftiReg). `registration/torchreg.py` is a thin subclass that converts its results to drift's `RegistrationResult` / `ImageSpace` / `JacobianStats` and re-exports its parameters and terms; fix algorithm bugs upstream in pyNiftiReg, then bump the dependency. Verified bit-identical to the former in-repo code on CPU. Algorithm: affine by Adam on NMI over a pyramid (centre-of-mass start, cosine LR decay; without the decay the affine jitters by one Adam step; **multi-start** at the coarsest level from identity scale and from the masks' per-axis spread ratio, keeping the better similarity: identity alone failed a Duke pair with a large size difference (scale 0.80 vs ~1.2), moment matching alone was misled by arms in thorax masks), then B resampled onto A's grid, then a B-spline SVF on **A's voxel grid** (not NiftyReg's world-aligned grid). Control-point spacing doubles per coarser level and is refined exactly between levels (`_refine`: nested knots, `bspline.from_dense`). Bending energy / linear elasticity are evaluated at the control points with 3-tap B-spline derivative stencils, in units of the spacing, like NiftyReg's `-be`/`-le`; profile weights stay in NiftyReg units and `RegistrationConfig.torch_params()` converts them with `torchreg.NIFTYREG_WEIGHT_SCALE` (be/le ×5, jl ×50). Calibrated on real data (24 labelled Duke pairs + 20 TotalSegmentator thorax pairs): ×10/×100 (the earlier phantom calibration) was too stiff on the thorax, ×3/×30 gave det J up to ~20 on hard breast pairs. Parzen NMI (cubic B-spline window, `index_add` joint histogram) peaks below 2 for identical images (≈1.55 at 64 bins), so torch `qc["nmi"]` values are not comparable with NiftyReg's `reg_measure`.
- GPU memory of torchreg grows ~0.3 GiB per million voxels (autograd through every squaring); use `registration.spacing` (the bank registers on resampled images and re-expresses the velocity on A's grid with `resample_field`) for full-resolution MRI. `pkill -f reg_f3d` also matches the shell running it — kill by PID.
